Consolidation is working again — for the first time on this dashboard, a sealed day converged after sealing. 08-17 has gone 923 → 414 files in 26 hours (−55%), and the sealed-consolidation queue 2,218 → 266. The previous snapshot called 08-17 "the worst sealed day ever recorded here"; it is now draining. 08-12 is the floor at 20 files / 3.1 GB, and 08-14/08-15/08-16 sit at 47–67.

Why it had stopped, and it was not throughput. plan_compaction_debt admitted a partition whenever any file was !is_sorted_run() — but that tag is written only by the OPTIMIZE path. Across 381 commits of the prod Delta log, 1,593 of 1,648 add actions carry no tags at all. So every partition holding a flush-written file — which is every partition — was permanently admitted, and ingest recreated the condition faster than consolidation could clear it. A treadmill, not a backlog. The codebase already knew: repair_verified_sorted's comment records that "the flush path sorts and stamps a correct footer WITHOUT the tag, so an untagged file is only a suspect", and Repair footer-checks before rewriting — consolidation did not, and read suspicion as proof. #200 gives consolidation file size, which is unambiguous, and leaves sortedness to Repair; #198 retires tasks for partitions the scan proves compliant, clearing 4,290 in its first pass.

08-13 is now the sharpest signal on this page. It reads 167 files — byte-for-byte the same count as the 08-18 snapshot, and the same four tenants (whale 47, dcad860a 43, 00000000 35, 28f62f01 32). It has not moved in four days while six younger sealed days converged past it. That is not a queue draining slowly; a partition skipped by six successors is not in the order the sweep reads. The mechanism is scheduling_class: sealed work is ranked strictly newest-first, and newer sealed days keep arriving, so 08-13 never reaches the head. Newest-first is right for freshness and wrong for a backlog — which is exactly the ordering #199 changed for the rollup tiers, and the same fix has not yet been applied to file hygiene. 08-13 is the evidence that it should be.

What to watch next. Whether 08-18 follows 08-17 down, and whether 08-13 finally moves. Those two questions separate "the fix works and the queue is merely ordered wrong" from "there is a second blocker behind it". No heavy maintenance class has ever been profiled, so if 08-18 stalls the next step is unit cost, not admission.
